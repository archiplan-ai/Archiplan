# The version does not carry the fact

The archive seals the model render and nothing else, so `version show v0021` rebuilds
the nodes and edges of that moment beside the world facts of today. Ask what conditioned
a node when v0021 was cut and no verb answers. The pressure is sharper here than for a
requirement: a requirement is retired rarely, while retiring a fact is the routine
event the wing exists for, so the question "what did this justify" gets asked far more
often of a fact than of anything else in the tree.

## Attractor

Deletion works forward and tells nothing backward. A fact goes because the world moved,
and afterwards nobody can name the behaviors that stood on it — so the operator hedges,
keeps the fact "just in case", and the wing loses the one operation it was built around.

## Resolution

Held, on the contract requirements already carry. A requirement does not enter the
archive either: `satisfied-by` resolves against the live model with no pin, because a
requirement is a standing claim and not a historical record. A world fact sits in
exactly that position, so the wing adds no deficit — it inherits one, shared with the
larger doc tree and already named by the deferred `versions-stay-searchable`.

Two records answer the backward question without any archive. The commit that removed
the file carries who retired it and why, as it does for every text in this repository.
And a plan that carried the fact names it on its tasks, so the work done under a
condition stays addressable through the plan that did it. Pinning the fact to a version
was considered and refused: a fact is a claim about the world, not about a render of the
model, and stamping it with a model version would date it by the wrong clock.
