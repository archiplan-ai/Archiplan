# The plan never meets the world

The wing's scenarios are executable, and no verb executes them. A plan pins a version,
owns tasks per node and curates the requirements each task carries. Nothing routes a
world fact into that: a task over a node whose behavior a fact conditions never learns
the fact exists, and the fact's Gherkin never becomes anything a wave runs. The half of
the unit that a machine can hold has no path to a machine.

## Attractor

The wing settles as documentation. The Gherkin is written once, parsed by `check`,
never run, and drifts from the code with nothing to notice — the exact rot the wing was
built to expose, now in the wing's own executable half. The link from a scenario to a
step definition, the one edge a run was supposed to decide instead of a person, has no
occasion on which anybody would author it.

## Resolution

The plan is the path. A task over a node carries the facts whose `covers` reaches it —
derived `a-task-carries-the-facts-that-cover-its-node` — so the condition and its
Gherkin sit in front of whoever writes the code, at the moment they write it, which is
also the moment a link from a step to a symbol becomes something somebody would author.
Carried, not curated: a task may drop a requirement it does not own, and it may not
drop a condition that applies to its node. The close then runs the same set, through
`the-plan-closes-on-the-world-s-scenarios`.
