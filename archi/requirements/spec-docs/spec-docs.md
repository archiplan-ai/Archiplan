# Spec docs

A model alone does not say why it must hold: the claims, the pressure applied and the
problems that started everything live in prose. That prose has to work like source —
parse deterministically, grep cleanly, retrieve as self-contained cards, and cross-check
against the model on every build, so a document can never silently rot against the thing
it constrains. Intents, requirements, stressors and sessions are therefore structured
markdown in the tree: machine fields in frontmatter, reasoning in fixed sections,
containment as hierarchy, slugs as the one reference currency — and the same check that
compiles the model compiles them.
